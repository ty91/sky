# CLI·데몬과 admin을 pnpm workspace로 구분한다

Tauri 데스크톱 앱과 React Native 모바일 앱을 같은 레포에서 개발할 수 있도록, 현재 제품을 `apps/sky`와 `apps/admin` 두 pnpm workspace 패키지로 구분한다. 이번 전환은 코드·의존성·테스트의 소유권과 빌드 경로를 정리하며 Slack, 대화 실행, 인증과 배포 동작은 유지한다.

CLI와 데몬은 `apps/sky`에 함께 둔다. 두 역할은 하나의 standalone 실행 파일, 제품 버전과 설치·업데이트 흐름을 공유하고 로컬 제어 모듈도 함께 사용한다. 지금 별도 패키지로 나누면 공통 인터페이스 추출까지 필요하므로, 접속 앱을 추가하기 위한 첫 구조 변경에는 포함하지 않는다. 역할과 생명주기에 관한 [ADR-0001](./0001-separate-cli-and-daemon.md), 호출 이름에 관한 [ADR-0006](./0006-select-runtime-role-by-invocation-name.md)은 유지한다.

Admin은 자체 React 의존성과 빌드·UI 테스트를 소유한다. 기존에 데몬 소스에서 가져오던 타입은 `@ty91/sky/admin-types`라는 타입 전용 진입점으로 모아 workspace 개발 의존성으로 명시한다. 기존 관리 인터페이스를 그대로 공유하는 단계이며 새로운 통신 규약을 정의하지 않는다.

제품 버전은 루트 manifest 한 곳에서 관리하고 두 앱 패키지에는 별도 버전을 두지 않는다. 일반 빌드 결과물은 각 앱의 `dist`에, standalone·release 결과물은 루트 `dist`에 둔다. 루트 스크립트가 패키지 빌드 순서와 제품 검증을 조립하고, 구현별 테스트는 앱에, 설치·업데이트 및 배포 도구 검증은 루트에 둔다. 추가 모노레포 실행 도구나 독립 릴리스 체계는 도입하지 않는다.

## 후속 작업

실제 앱을 추가할 때 `apps/desktop`, `apps/mobile`을 만들고, 통신 규약과 클라이언트 로직의 공유가 필요해지면 `packages/protocol`, `packages/client`를 추출한다. 에이전트 구현은 당분간 데몬 패키지 안에 두며 빈 패키지를 미리 만들지 않는다. 앱은 로컬 또는 원격 Mac의 `skyd`에 접속하는 클라이언트를 기본 방향으로 한다.

1. Slack 연결과 에이전트 런타임의 시작·종료 및 상태 관리를 분리해 Slack 미설정이나 연결 실패가 앱의 대화를 막지 않게 한다. 파일 전송과 예약 알림에 남은 Slack 전제도 후속 작업에서 다룬다.
2. Sky 자체 대화 ID를 도입하고 Slack 채널·스레드는 외부 식별자로 연결한다. 앱에서 같은 대화를 조회·재개하는 모델과 여러 채널 동시 전송 정책은 별도로 결정한다.
3. 앱용 메시지 전송·이력 조회·응답 스트리밍과 재연결을 설계한다. 백엔드 세션 복원과 화면에 표시할 이력을 구분하고, 연결이 끊겨도 데몬 작업을 지속하며 재접속 시 상태와 결과를 복구한다.
4. 브라우저의 same-origin cookie와 재시작 시 만료되는 admin session을 넘어, 앱의 기기 등록·재접속·접근 철회에 맞는 인증 흐름을 설계한다.
