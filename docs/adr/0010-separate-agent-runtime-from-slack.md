# 에이전트 런타임을 데몬이 소유하고 Slack을 선택적 연결로 둔다

앱이 로컬 또는 원격 데몬에서 대화하려면 Slack 미설정이나 장애가 에이전트 준비를 막지 않아야 한다. 데몬은 대화 관리자와 저장소를 먼저 준비하고 Slack 연결만 독립적으로 시작·재시도한다. Slack 연결을 재시도할 때 런타임 전체를 다시 만드는 기존 구조는 다른 접속 경로의 진행 중 대화까지 닫으므로 채택하지 않는다.

`runtime.ready`는 대화를 받을 준비가 되었다는 뜻이며 모델 제공자의 인증이나 요청 성공을 보장하지 않는다. Slack의 미설정·연결 중·재시도 상태는 따로 보고한다. 설정의 `complete` 역시 에이전트 필수 설정만 판단한다. Slack 토큰 일부만 있는 경우에는 연결을 시작하지 않고 진단에서 부분 설정을 알린다. 일반 설정과 credential 변경은 기존처럼 명시적 데몬 재시작으로 적용한다.

공통 에이전트는 Slack 세션 키를 해석하거나 Slack 도구를 기본으로 제공하지 않는다. Slack 쪽에서 대화의 전달 문맥과 파일·예약 도구를 조립한다. 기존 Slack 대화 식별자는 유지하며 Sky 자체 대화 ID, 앱용 통신 규약과 결과 보관은 별도 후속 작업이다. 내부 대화 실행도 데몬의 작업 lease에 참여해 신규 입력 차단과 drain 제한 시간을 따른다.

이 결정은 [ADR-0001](./0001-separate-cli-and-daemon.md)의 process 감독 및 설정 snapshot 원칙을 유지하면서 Slack 장애가 전체 runtime을 degraded로 만드는 부분을 변경한다. 실제 소켓 재연결도 데몬이 관리해 재시도 상태와 연결의 소유권을 일치시킨다.
